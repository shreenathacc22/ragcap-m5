ragcap

A multi-agent RAG system (LangGraph router, document RAG with grade and rewrite, SQL agent, general agent) on Postgres + pgvector and local models, built to reproduce a colleague's capstone design and then measured: a frozen evaluation set, an unseen set, repeated runs, and a version-aware retrieval filter with an OFF/ON proof. Built, tested and run on an Apple M5 Pro with local models: no API key, no cloud service, no admin rights.

100%router accuracy on the tuned set and on 25 unseen questions
92.6%answers correct, tuned set (80% on the unseen set; identical over 3 runs)
51.6% → 0.0%superseded chunks retrieved, version filter OFF → ON
≤1 mscost of the filter (12–13 ms either way, interleaved, 96 calls each)
96%answers correct on the unseen set with a qwen3:8b second-opinion grader (80% without)

The flow

Every node appends its milliseconds and tokens to the trace. The version filter is one WHERE d.superseded = false applied before the vector ranking, behind a switch, so an old document version can never compete for a slot.

From pre-work to troubleshooting

1. Pre-work
Requirements (no admin rights, ~12 GB disk), what gets built, the design decisions in the code, and the rules that keep results honest: test sets frozen in git before the code, never tuned on.
2. Prepare
uv and Python 3.12, Ollama as a standalone binary, two required models (2.3 GB). Nothing installed system-wide.
3. Implement
Native Postgres + pgvector through pgctl.sh, schema, ingestion with version metadata, the LangGraph, FastAPI + web page + Gradio, the P&ID branch, optional Docling.
4. Test
Clean-start check, fingerprints, the version filter OFF/ON, 18 scenarios, 3 repeated runs per test set, P&ID tags and questions, browser checks.
5. Operate
services.sh start / status / check, backups, model profiles (lean or recommended), change control.
6. Troubleshoot
Every problem met on this machine with its cause and fix: socket path limit, ports, sleep, model memory, and a stage-by-stage probe for wrong answers.

At answer level the filter raised the 27-question score from 88.9% to 92.6%: with old versions excluded the six retrieved chunks hold more distinct documents (multi-hop 0/2 → 1/2). Version questions were 8/8 both ways because each current runbook names its former value; the retrieval-level numbers are the proof the design rests on.

P&ID branch: drawings into the same index

Three synthetic P&IDs drawn from one template with every tag and relation in a ground-truth file, 12 golden questions, and a vision model writing one fact per sentence into the index (qwen2.5vl:3b, 5–12 s per drawing).

Measureqwen2.5vl:3b (default)qwen2.5vl:7b

Right drawing retrieved12/1212/12

With the 7b model every tag is read and the right drawing is always retrieved. The answers that still fail need reasoning over the drawing's connections (which valve is on the suction side); neither a stronger grader nor an 8B answering model fixed them, so the next step is storing connections as structured data, not a bigger model.

Run it yourself

git clone https://github.com/shreenathacc22/ragcap-m5 && cd ragcap-m5
ollama pull llama3.2:3b; ollama pull nomic-embed-text   # no Docker: pgctl.sh runs Postgres natively
./recreate.sh                      # database, ingest, checks, fingerprints, OFF/ON ablation, smoke questions
./services.sh start && ./services.sh check   # after a reboot: ends CLEAN START OK
.venv/bin/uvicorn api:app --port 8000   # then http://127.0.0.1:8000/
VERSION_AWARE=0 .venv/bin/python try.py "At what disk utilisation should a broker page?"   # the trap: often 85%
.venv/bin/python try.py "At what disk utilisation should a broker page?"                  # the fix: 75%

Needs Ollama and Python 3.12; Postgres + pgvector run natively from a pip wheel (no admin rights). A few minutes plus model downloads; the step-by-step manual is the install guide (PDF). recreate.sh exits 1 if any fingerprint differs from the recorded ones.

Decisions and limits, stated plainly

  • Scores come from 3 repeated runs per test set (identical on this machine); the failing case ids are listed, and a scorer is never changed after seeing a result.
  • Next.js was descoped: the streaming endpoint is the design; a static page proves it without a toolchain.
  • Docling runs in its own environment for PDFs and Office files with tables; LangSmith is wired but needs a real key.
  • This site is static: the replay above is recorded, not live.
